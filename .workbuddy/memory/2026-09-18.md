# 2026-09-18

## CCRouter v0.1 现状核查 + 业界路由框架对比

读取了 `CCRouter-v0.1-architecture.md` 与 `CCRouter-route-design.md`，并核对了
`packages/` 实际代码与 demo 接线，对照 TheRouter / ARouter / WMRouter / auto_route / ff_annotation_route。

### 已落地（代码已确认）
- 静态门面 `CCRouter`：navigator / service<T> / command / query / action / event / openSession / closeSession / shutdown / initialize / 诊断 getter。
- 核心导航管线：push/replace/go/reset/open/pop/canPop + maybePop / popAndPush / popUntil / pushAndRemoveUntil，带类型安全返回值。
- 两层拦截器（global + route），proceed/cancel/redirect + 重定向环检测。
- 内存 Adapter（Pure Dart 测试）、GoRouter Adapter（Shell/Outlet、BottomSheet/Dialog、Observer）。
- Deep Link Ingress（internal/external origin）、Session Scope、Trace/诊断、Command/Query/Action/Event 调度、Shell 定义、Path/URI/Regex Pattern。
- demo 为手写 `CCComponentRegistrar` + `CCComponentManifest`（无代码生成）。

### 关键缺失（与文档承诺和业界框架的差距）
1. **无 `ccrouter_annotations` + `ccrouter_generator` 包**：注册全靠手写 `register()`，没有注解 + build_runner 生成。文档核心卖点「生成优先 / 类型安全 Intent+Codec 自动生成 / 组件 Registrar 自动生成 / 冲突检查 / 文档生成」均未实现。这是最大短板（TheRouter/ARouter/auto_route 均注解驱动）。
2. **InitTask DAG / Gate / FlowTaskExecutor 未实现**（文档 §13 完全空白）。
3. **无 `ccrouter_test` 包**：`CCRouterTest.run` + `CCServiceOverride` 隔离测试 Runtime 未实现。
4. **无路由文档生成**（cc_routes.json/.md）。
5. **无 Service 方法级 Proxy / AOP**、无参数自动注入到页面（Codec 仅规划）。
6. **无远端路由表下发 / 动态化 / H5 降级**（Flutter 下合理排除，但 TheRouter 有）。
7. **无 IDE 插件 / 路由反查 / 迁移工具**（TheRouter 有 AS 插件与 ARouter 一键迁移）。

### 结论
CCRouter 在「契约语义分层 / 类型安全 / Scope 生命周期 / 无反射 Pure Dart / 多后端 Adapter / 安全 Origin 模型」上领先于 TheRouter/ARouter；
但在「注解驱动代码生成 + 编译期校验 + 文档 + 初始化编排 + 测试替身 + 生态工具」上明显落后，当前是手写注册的 Runtime 内核，尚未成为可规模落地的路由框架。
优先补 `ccrouter_generator` + `ccrouter_annotations` 是性价比最高的下一步。

## 拦截器层面对比 TheRouter（代码级核查）
CCRouter 拦截器现状（`navigation_interceptor.dart` + `navigation.dart`）：接口 `CCNavigationInterceptor.intercept(context)` 仅收 `CCNavigationInterceptorContext`，返回值 sealed 三态 `Proceed/Cancel/Redirect`；执行在**路由匹配之后**（`_buildNavigationRequest` 之后、`adapter.navigate` 之前）；`CCNavigationRequest` 是 immutable（`final`），拦截器**无法就地修改当前请求**；global（注册顺序）+ route（`interceptorIds` 显式声明）两档；redirect 重跑匹配+拦截链并计 `redirectDepth`（上限 8，超了抛 `CCRouteRedirectLoopError`）；cancel→`CCRouteCancelledError`。

相对 TheRouter（四切面：`NavigatorPathFixHandle` 匹配前改 path / `RouterReplaceInterceptor` 匹配后 in-place 替换 RouteItem / `RouterInterceptor` 拦截 / `DegradeHandler` 失败兜底 + `registInterceptorForURLString` pattern 通配 + 跳转回调 + 远端路由表覆盖）**缺失/偏弱**：
1. 无「匹配前 Path-Rewrite 阶段」——改 path 只能 redirect（重跑全套、占 redirectDepth）。
2. 无「in-place RouteItem 替换」——不能改当前不可变 request 的参数/目标而不触发重定向。
3. 无「拦截器按 URL pattern 通配绑定」——只有 global/route 两档，缺 pattern 范围档（如 `/admin/*` 鉴权）。
4. 无「降级处理器 Degrade」——cancel/error 直接抛，无导航失败的 onError fallback 钩子。
5. 弱「post-navigation 切面」——有 `Future<R?>` 同步结果 + adapter 级 Observer，但无 Router 统一 after-hook。
6. 弱「优先级」——global 靠注册顺序/字符串 id，无显式 `priority` 字段。
7. 无「运行时可插拔 redirect/patch 规则表」（远端配置驱动）。
反超点（补时勿丢）：sealed 返回值比 TheRouter 的「返回 BOOL+自己 navigation()」更类型安全、无 re-entrant；`FutureOr`+`CCCancellationToken` 异步+取消；redirect 保留 origin 且显式环检测；context 带 `ownerComponentId`/`origin` 安全模型。

用户纠正（16:13）：TheRouter 不止路由拦截器，其完整切面谱系含 路由拦截 RouterInterceptor / 路径修正 NavigatorPathFixHandle / 路由替换 RouterReplaceInterceptor / 降级 DegradeHandler / **ActionManager（action 拦截，远端下发业务 action）** / **ServiceProvider 服务获取切面** / **FlowTask 初始化编排拦截** / 跳转完成回调 / 按 URL pattern 通配 / 远端路由表+重定向覆盖。关键新发现：CCRouter 拦截器 100% 挂在 nav 通道（`_runInterceptors` 仅在 `navigation.dart` 调用；`registry.registerRouteInterceptor`/`runtime_host._routeInterceptors`/`facade` 的 command/query/action/event 均无 intercept 钩子）—— 而四通道 Command/Query/Action/Event 当前**零切面**，多通道切面上反不如 TheRouter（TheRouter 至少 nav+action 两路）。补齐方向：把拦截器抽象为通用通道切面，覆盖 nav+action+command/query/event，借四通道反超 TheRouter。
