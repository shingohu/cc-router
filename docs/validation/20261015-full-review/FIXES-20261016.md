# CCRouter 审查问题修复（2026-10-16）

本记录补充 [2026-10-15 审查报告](REPORT.md)，不改写历史审查结果。三项修复已落到原 main 工作目录与 predictive-back worktree；未提交、推送或合并。

## 根因与实施方案

采用三个局部修复，保留现有 API 和预测返回 opt-in。架构重写的回归面更大；只捕获异常或仅替换 SDK 都不能解决资源所有权与旧手势提交的问题。

| 问题 | 修复位置 | 已实施行为 |
| --- | --- | --- |
| F1：首次 Watch 快照异常绕过清理 | main 与 predictive 的 Generator | child 创建后的初始化、监听器、Timer 和首次快照均进入统一清理边界；先停止 child、清理资源，再释放 ownership/generation locks。单项清理错误不跳过其它清理。失败状态为 inactive `failed`，停止镜像修复 Timer，不发成功 `stopped` |
| F2：标准 Flutter 无 `TargetPlatform.ohos` | predictive 的测试 | 按用户要求以 `Platform.operatingSystem == 'ohos'` 判断，再通过 `TargetPlatform.values.byName(Platform.operatingSystem)` 解析；iOS 用例保留 |
| F3：能力查询解除旧手势提交保护 | predictive 框架 | tracking 期间保留原 handler，直到 commit/cancel；Adapter 销毁后查询 `popGestureEnabled` 不再使迟到 commit 误退页面，后续新手势仍恢复 Flutter 行为 |

F1 两处分支的生产文件已核对相同，保留了各分支原有测试 fixture 差异。没有新增业务 API。同步更新中英文 README、CLI/接入 Skill、相关 reference 与生命周期文档；补齐 predictive 文档索引。

新增真实 Watch IO 故障回归：临时暂停自己的 CLI、将生成文件设为不可读，验证失败退出、child 已退出、status 为 inactive/failed、不发送 stopped，并恢复文件权限后重新生成以验证锁释放。该 POSIX 权限测试在 Windows/root 环境跳过。

新增手势 commit/cancel 两个回归：start → Adapter dispose → getter 查询 → 终态；验证原页面与动画状态、下一次手势正常退出、资源仅销毁一次。修复前 Watch 用例实际返回 255；手势 commit 用例实际误退页面，均有失败证据。
